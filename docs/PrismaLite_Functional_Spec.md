# PrismaLite_Functional_Spec

## 1. Введение

Функциональное техническое задание описывает полную функциональность PrismaLite: роли пользователей, сценарии, бизнес-правила, интеграции, отчёты, фильтры и UI. Документ ориентирован на команды руководства, аналитиков, backend/frontend и DevOps, определяя, что именно должно быть реализовано.

## 2. Пользовательские роли и права

### 2.1 Аналитик
- Просмотр чеков и событий.
- Просмотр видеоматериалов, синхронизированных с событиями.
- Использование фильтров и построение отчётов.
- Создание и обработка инцидентов.

### 2.2 Администратор
- Управление пользователями и ролями.
- Настройка магазинов, касс, камер.
- Управление правилами, лицензиями.
- Настройка интеграций POS и DVR.

### 2.3 Оператор (оперативный режим)
- Просмотр live-видео.
- Получение уведомлений о нарушениях.
- Подтверждение/отклонение инцидентов в реальном времени.

### 2.4 Инженер
- Настройка серверов.
- Управление интеграциями, сетью, NTP.
- Поддержка POS агента и видеомодуля.

Роли комбинируются через ACL (подробнее в `PrismaLite_Security.md`).

## 3. Сценарии пользователей

### 3.1 Аналитик — просмотр чека
1. Выбрать магазин и/или кассу/кассира.
2. Выполнить поиск по номеру чека, периоду или SKU.
3. Просмотреть хронологию событий.
4. Автоперемотка видео на выбранное событие.
5. Создать инцидент при необходимости.

### 3.2 Администратор — добавление кассы
1. Ввести IP-адрес кассы.
2. Указать идентификатор кассира/магазина.
3. Выбрать тип кассового ПО (Set Retail/Frontol).
4. Проверить связь.
5. Привязать камеру (если требуется).
6. Сохранить и активировать.

### 3.3 Оператор — работа в оперативном режиме
1. Получает список активных нарушений.
2. Кликает по инциденту.
3. Открывается live-видео + чек.
4. Подтверждает или отклоняет нарушение.

### 3.4 Инженер — добавление DVR
1. Добавить DVR с указанием типа (Hikvision/Dahua/CSI).
2. Выполнить тест подключения.
3. Назначить камеры к кассам/магазинам.
4. Проверить live/архив потоки.

## 4. Бизнес-правила

### 4.1 Событийная модель

- Основана на реестре событий `События.txt`.
- Типы: сканирование товара, отмена позиции, изменение количества, подытог, регистрация чека, открытие денежного ящика, маркировка и т.д.
- Событие содержит: `timestamp`, `store`, `pos`, `cashier`, `event_code`, `payload`.
- События DOC_BEGIN/DOC_END формируют чек.

### 4.2 Правила фиксации нарушений (примеры)

- Двойное сканирование товара (код R001).
- Уменьшение количества после сканирования.
- Отмена после подытога.
- Сканирование вне чека.
- Использование карты из чёрного списка.
- Подозрительно малая сумма чека.

Полный список — в документе `PrismaLite_Rules_and_Incidents.md`.

### 4.3 Правила интеграции с видео

- Видео должно начинаться минимум за 5 секунд до события.
- При выборе события видео перематывается в соответствующую точку.
- Для возвратных чеков используется исходный чек и его видео.

## 5. Фильтры

Доступны комбинируемые фильтры:
- магазины/тенанты;
- кассы, кассиры;
- типы событий/нарушений;
- временные диапазоны;
- SKU/товары;
- статусы инцидентов;
- правила и severity.

Фильтры применяются к спискам чеков, событий, инцидентов, отчётам и live-панелям.

## 6. Отчёты

### 6.1 Аналитические отчёты
- События по кассирам (количество, типы, динамика).
- Статистика по товарам и скидкам.
- Отчёт по нарушениям (heatmap по магазинам/кассам).
- Чеки по кассирам, время между позициями.
- Отчёт по времени реакции на инциденты.
- Отчёт по оплатам и картам.

### 6.2 Экспорт
- PDF — для менеджмента.
- Excel/CSV — для анализа.
- Автоматическая отправка по расписанию (доп. опция).

## 7. Интеграции

### 7.1 Set Retail
- Форматы: XML, JSON, бинарные логи.
- Поддержка событий: DOC_BEGIN, EVENT, MARK_SCAN и др.
- Привязка кассира и магазина.
- Подписи и проверка целостности.

### 7.2 Frontol
- Источники: лог-файлы, «масло», API.
- События AddItem, VoidItem, QtyChg, Payment, Total и др.
- Нормализация и маппинг на единую модель.

### 7.3 DVR/видео
- Hikvision, Dahua, CSI.
- Работа через backend-прокси, без прямого доступа из UI.
- Синхронизация с событиями.

### 7.4 PostgreSQL / внешние сервисы
- PostgreSQL как основная БД.
- Подключение к системам лицензирования, мониторинга.

## 8. Лицензирование

- Лицензии на количество касс, аналитиков, видеоканалов.
- Офлайн-проверка лицензий (ключи).
- Лицензионный сервер ведёт учёт лимитов, статус доступен через API.

## 9. UI-описания (сводно)

### 9.1 Главный экран (Dashboard)
- список магазинов и их статус;
- активные инциденты;
- быстрый переход в аналитику/live.

### 9.2 Аналитический режим
- Видео + чек (двухпанельный интерфейс).
- Список событий (timeline) с цветовой подсветкой.
- Инструменты аналитика (заметки, создание инцидента).

### 9.3 Оперативный режим
- живой просмотр камер (4/9/16 плиток);
- панель уведомлений/алертов;
- карточка инцидента с подтверждением.

### 9.4 Настройки администратора
- магазины и кассы;
- камеры и DVR;
- пользователи и роли;
- правила и лицензии.

Полное UI-описание в `PrismaLite_UI_Guide.md`.

## 10. Список событий (частичный)

Основан на `События.txt`:
- 11 — Начало документа.
- 12 — Конец документа.
- 13 — Аннулирование документа.
- 20 — Добавление товарной позиции.
- 23 — Отмена товара.
- 25 — Изменение количества.
- 38 — Переход на чековую позицию.
- 39 — Сканирование вне чека.
- 60 — Назначение скидки.
- 70/73 — Оплата наличными/картой.
- 90 — Подытог.
- 92 — Регистрация чека.
- 100 — Открытие денежного ящика.
- 112 — Ответ оператора.

Полный список поддерживается в отдельном справочнике.

## 11. API (сводно)

Backend предоставляет REST API:
- `/events/ingest` — приём событий.
- `/events/by_check/{id}` — события по чеку.
- `/video/live`, `/video/replay` — доступ к видео.
- `/incidents` — CRUD инцидентов.
- `/rules` — управление правилами.
- `/reports/generate` — построение отчётов.
- `/auth/*` — авторизация и ключи.

Полная спецификация — `PrismaLite_API_Reference.md`.

## 12. Нефункциональные требования

- Время обработки события ≤ 300 мс.
- Отображение видео по событию ≤ 3 с.
- Хранение событий не менее 12 месяцев.
- Поддержка 30+ магазинов, 1 млн событий/сутки.
- Поддержка 20+ одновременных live-потоков.
