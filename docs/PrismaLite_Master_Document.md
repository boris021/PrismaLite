# PrismaLite_Master_Document

## 1. Назначение продукта

PrismaLite — система контроля кассовых операций, видеоаналитики и мониторинга, ориентированная на ретейл-сети. Платформа фиксирует события кассовых систем, синхронизирует их с видеопотоками, анализирует нарушения и предоставляет инструменты для аналитиков, операторов и администраторов.

Ключевые задачи:

- сбор и нормализация кассовых событий (совместимость с SET Prisma);
- определение инцидентов по правилам;
- оперативное отображение видео и чеков;
- централизованное управление магазинами, кассами, камерами;
- расширенная аналитика, отчёты, пользовательские правила.

## 2. Общие цели

- Автоматизировать контроль кассовых операций.
- Снизить потери за счёт выявления нарушений и отклонений.
- Предоставить единый центр наблюдения за сетью магазинов.
- Соединить кассовые события с видеоархивом.
- Обеспечить расширенную аналитику, отчёты и кастомные правила.

## 3. Обзор модулей

### 3.1 Модуль получения кассовых событий

Принимает события от кассового ПО (SET Retail, Frontol и др.), поддерживает операции с чеком, действия кассира, маркировку, оплаты и другие события из реестра `События.txt`. События валидируются, нормализуются и сохраняются в БД.

### 3.2 Модуль видеонаблюдения

- синхронизация событий и видеопотоков;
- поддержка нескольких DVR/IP-камер;
- быстрый поиск по времени/событиям;
- проксирование RTSP → HLS/WebRTC.

### 3.3 Аналитический модуль

- отображение чеков и событий;
- контроль операций (аналог Prisma 7);
- поиск инцидентов, фильтрация по кассе/кассиру/типу события;
- интеграция с видео.

### 3.4 Модуль оперативного наблюдения

- live-просмотр камер (квадраторы);
- уведомления о нарушениях;
- подтверждение/отклонение инцидентов.

### 3.5 База данных и API

- PostgreSQL как основная БД;
- единая схема для событий, чеков, видео, пользователей;
- Backend API (REST/WebSocket) для UI, агентов и интеграций.

## 4. Общая логика работы

1. POS отправляет события (структура, совместимая с SET Prisma / Frontol).
2. Сервер получает, валидирует, нормализует и записывает их в БД.
3. Видеопоток пишется DVR; backend хранит ссылки/сегменты.
4. Аналитик выбирает чек → система вычисляет временные метки → отображает соответствующее видео.
5. Rules Engine анализирует события и формирует инциденты.
6. Оперативный режим показывает live-состояние магазинов и активные нарушения.

## 6. Глоссарий

- **Event** — нормализованное кассовое событие.
- **Check** — документ продажи, объединяющий события `DOC_BEGIN/DOC_END`.
- **Incident** — нарушение, созданное по правилу.
- **DVR** — видеорегистратор (Hikvision/Dahua/CSI).
- **POS Agent** — агент, собирающий события с кассового ПО.
- **Tenant** — отдельная розничная сеть/клиент.
